Co dokładnie jest w Virel Beta 2?

To nie jest tylko nowa tapeta i kilka zaokrągleń. Build 26000.210 rozwija warstwę wizualną, system okien, pliki, wyszukiwanie, powiadomienia, bezpieczeństwo, przestrzenie robocze, odzyskiwanie i narzędzia dostępne z wielu miejsc.

Interface foundation

Glass 5 + Wallpaper DNA 2.0

Kolory tapety wpływają na semantyczną paletę systemu, ale powierzchnie pozostają neutralnym szkłem zamiast przypadkowo kolorowanych ramek. Start, Settings, Files, Control Center, Dock, context menus, notifications i okna aplikacji korzystają z tego samego materiałowego języka.

✓94% transparency w założeniach Glass 5.1 oraz cache blur 72 px opisany w buildzie.
✓Wallpaper DNA może być wyłączone niezależnie od stylu ikon.
✓Connected UI 5 współdzieli geometrię, spacing i stany interakcji.
✓Transient surfaces mają wspólne fade + slide i zamykają się po kliknięciu poza nimi.

System w warstwach

Więcej niż to, co widać na pulpicie.

Minimalny interfejs nie oznacza małej liczby funkcji. Nexora celowo przenosi część możliwości do Search, Lens, kontekstu, skrótów i usług działających w tle.

⌁

Encode App

Ochrona aplikacji hasłem z verifierami PBKDF2-SHA256. Zmiana hasła aplikacji wymaga starego hasła; zdjęcie blokady wymaga hasła konta Nexora.

Nexora Technologies

O firmie i idei projektu.

Nexora Technologies jest marką skupioną wokół tworzenia własnego oprogramowania, interfejsów i eksperymentalnych produktów. Nexora OS jest centralnym projektem: miejscem, w którym język wizualny, aplikacje i pomysły systemowe mogą być testowane jako jedna całość.

Mission

Interfejs ma być spokojny. System może być potężny.

W Nexorze liczba funkcji nie ma być mierzona liczbą stale widocznych ikon. Zaawansowane możliwości mogą żyć w Search, Lens, PPM, skrótach, Feature Center i automatycznych mechanizmach. Dzięki temu użytkownik widzi to, czego potrzebuje teraz, a reszta pozostaje dostępna wtedy, kiedy ma sens.

Design philosophy

Connected UI zamiast kolekcji przypadkowych przycisków.

Elementy należące do jednej czynności powinny wyglądać i zachowywać się jak jedna grupa. To oznacza wspólną geometrię, promienie, spacing, stany hover/active i przewidywalne animacje. Connected UI ma być zasadą konstrukcyjną, nie efektem specjalnym.

Product thinking

System i aplikacje projektowane razem.

Nexora nie traktuje Files, Settings, Browser czy Documents jako obcych programów „doklejonych” do pulpitu. Mają korzystać z tego samego systemu okien, materiałów, akcji, przestrzeni i kontekstu. Celem jest wrażenie jednego produktu od uruchomienia po codzienną pracę.

Experimentation

Projekt może zmieniać kierunek.

Beta oznacza miejsce na eksperyment. Nie każdy pomysł musi przetrwać do stabilnego wydania. Ważniejsze jest wychwytywanie regresji, sprawdzanie użyteczności i upraszczanie tam, gdzie system zaczyna być przeładowany.

FAQ

Najczęstsze pytania.

Ten build jest lokalnym desktop environment rozwijanym głównie w Pythonie i PySide6. Uruchamia się na systemie hosta. Projekt może eksperymentować z własnym doświadczeniem systemowym, ale obecna paczka nie jest niezależnym kernelem/ISO instalowanym jak Windows czy klasyczna dystrybucja Linux.

README opisuje macOS, Windows i Linux. Wymagane są Python 3.10–3.13, PySide6, Pillow i psutil. Część funkcji macOS wymaga odpowiednich frameworków PyObjC.

Nie. To celowe. Zaawansowane możliwości mają być odkrywane przez Search, Lens, context menus, skróty i kompaktowe menu, żeby system nie zamienił się w dashboard pełen przycisków.

Automatyczne testy nie pokrywają całego doświadczenia wizualnego i platformowego. Raport wprost zaznacza, że realne macOS/Windows/Linux z PySide6 są nadal wymagane do walidacji compositor-specific visuals, Qt runtime, WebEngine, natywnych API audio/brightness i Touch ID.
